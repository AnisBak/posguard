# posguard v0.1.0 (2026-11-14)

First tagged release: **Milestone 1 (core protection and outage-safe checkout)**. This is an early release for evaluation and feedback. It isn't published to Maven Central yet, and the APIs may still change before 1.0.

posguard is an open-source Android toolkit that protects the **merchant app around a certified payment engine**. It never replaces the engine, never touches card data, and makes no PCI claim.

## What's included

| Module | What it does |
|---|---|
| `posguard-core` | `PosGuard.preflight()` with fail-safe parallel signals, `GuardVerdict` (Allow/Warn/Block), `ReasonCode`, configurable `GuardPolicy` (conservative defaults, strict properties loader, relay-risk capped at WARN), and the `TransactionLedger` contract with an explicit state machine |
| `posguard-ledger` | Room journal: idempotency keys, atomic state-machine-checked transitions, recovery by key after crashes and network drops, the engine outcome kept on closed records, and a WorkManager recovery worker |
| `posguard-integrity` | Overlay detection (obscured touches), screen-recording detection (API 35+), accessibility, debugger, and root/emulator signals, plus `PaymentScreenProtection` (FLAG_SECURE, obscured-touch filtering, hiding overlays on API 31+) |
| `posguard-integrity-play` | Optional Play Integrity signals (device, app, app access risk) sharing one verdict fetch, with an offline fake |
| `posguard-telemetry` | Fail-closed scrubber (PANs, track data, emails, phones, sensitive keys), v1 event schema, bounded buffer, and pluggable sinks (in-memory, rotating JSON lines) |
| `mock-payment-engine` | **Not real.** A SoftPOS stand-in with a deduplicating processor and six failure modes |
| `demo-app` | "Sunrise Market": demo scenarios 1–5 from hidden Demo controls, a Why-blocked panel, and a live scrubbed telemetry panel. Fully offline |

## Verification

- 203 unit and Robolectric tests across all modules, including the full ledger recovery matrix, a crash/relaunch simulation, a schema migration test, and end-to-end scenario tests asserting **at most one processor charge** per payment.
- Every Android API checked against developer.android.com, with minimum API levels noted in code. Lint is clean.
- Demo scenarios 1–5 run end to end on a Pixel 9 emulator (API 36). FLAG_SECURE was confirmed on the payment window, and no test card numbers appeared in logcat.

## Known limitations

- **Not yet verified on real devices:** obscured-touch detection with a real overlay app, screen-recording detection on an Android 15+ phone, and the protection level of `HIDE_OVERLAY_WINDOWS`.
- **The real Play Integrity provider** needs Play Console setup and a backend that decodes tokens. Only the fake source has been exercised.
- **Overlay detection** needs a touch while the overlay is present. Android has no API to query overlays directly.
- **Screen-recording detection** is unavailable below API 35. Payment screens are still protected by FLAG_SECURE.
- **Never-charged-twice** depends on the payment engine supporting status lookup by idempotency key.
- **v1 → v2 ledger migration:** records completed under v1 keep an unknown (null) outcome.
